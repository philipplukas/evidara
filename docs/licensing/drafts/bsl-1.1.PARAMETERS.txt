Notes before adopting BSL for this repository:

1. BSL is NOT open source. It is not OSI-approved. Calling it open source in
   marketing copy is the single most common mistake made with it, and
   marketing/src/lib/content.ts requires an evidence code path for every
   claim (ADR-0039) — a BSL claim would have to be worded accurately there.

2. BSL applies per release. Each release carries its own Change Date, so a
   release made in 2027 under a fixed 2030-01-01 Change Date converts sooner
   after publication than one made in 2026. Decide fixed-vs-rolling before the
   first release, not after.

3. BSL says nothing about third-party components. THIRD-PARTY-NOTICES.md is
   still required, and the LGPL/MPL obligations in the dependency inventory
   are unaffected by it.

4. If the WorkflowCommandEnvelope extraction in §4(a) of the brief goes ahead,
   it must NOT be BSL. A schema nobody may use in production is a schema
   nobody adopts.
