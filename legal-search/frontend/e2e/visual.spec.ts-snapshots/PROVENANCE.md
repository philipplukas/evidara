# Visual baseline provenance

Every image in this directory is an assertion about what the product looks like.
This file records where each one came from.

## Why this file exists (#611)

For most of this repo's life these baselines were regenerated by running
`npm run e2e:visual:update` on a workstation and committing the output. Three
separate times, that captured a live bug and shipped it as the definition of
correct:

| Baseline | What it certified | For how long |
|---|---|---|
| `workspace-desktop-linux.png` | the #605 filter rail, ~260px too narrow | ~3.5 months |
| `app-header-linux.png` | the retired serif-"E" brand tile, after `BrandMark` replaced it | ~3 months |
| `empty/error/workspace-*-mobile.png` | the #674 filter badge reading "2" | blessed 5 min *after* the fix landed |

None of it ever failed CI, because `playwright.config.ts` carried a
project-level `maxDiffPixelRatio: 0.06`. On a 1600x900 full-page shot that is
~86,000 pixels of licensed drift — more than enough to hide an entire mislaid
region, a replaced logo, or a changed sentence. The suite could not go red, and
its greenness was read as evidence.

The tolerance is gone. Two things keep it gone:

1. **Zero tolerance** — `toHaveScreenshot` runs at Playwright's default, which
   allows zero differing pixels. A wrong baseline now fails on a clean runner.
2. **This ledger** — `scripts/check_visual_baseline_provenance.py` fails CI and
   pre-commit if a `*.png` here changes without a matching entry below.

## How to regenerate

**Preferred — let CI do it.** Add the `visual-baseline-refresh` label to your
PR, then push. The job regenerates on `ubuntu-latest`, the same runner that
verifies, and appends an entry here automatically. You still have to write the
`Reason:` line before merging.

This matters more than it sounds. Font rasterisation differs between machines;
a baseline blessed on a workstation encodes that workstation's text rendering,
which no other machine reproduces byte-for-byte. Zero tolerance is only
sustainable when generation and verification share an environment.

**Local regeneration** is still possible and sometimes necessary. If you do it,
add an entry below by hand — and be aware of the trap that caused all three
failures above: `reuseExistingServer: true` means Playwright will happily attach
to *whatever* is already listening on port 3101. If that is a stale dev server
or a docker-compose container from another checkout, you will photograph a build
that is not the one you are testing. Confirm what you are hitting first.

A `Reason:` of "the tests were red" is not a reason. That is the mechanism this
file exists to catch.

## 2026-07-19 — #611 — findings from the first zero-tolerance run

- Generated by: no images regenerated in this entry — diagnosis only.
  Regeneration is deferred to the `visual-baseline-refresh` CI job in this same
  PR, deliberately. Blessing these locally would encode this workstation's font
  rasterisation into images that a GitHub runner then has to reproduce
  byte-for-byte, which is the trap that makes people reach for a tolerance in
  the first place. The `detail-sheet-mobile` finding below is that delta,
  measured.
- Reason: with the project-level `maxDiffPixelRatio: 0.06` removed, 6 of 14
  snapshots failed. Each failure was diagnosed to an exact pixel region before
  any image was touched — the point of #611 is that "make it green" is the
  mechanism that caused the bug, so every diff below carries a verdict on
  whether the BASELINE or the APP is wrong. In all five content cases: the app
  is right and the baseline is a photograph of something the product no longer
  does.
- Diffs were pinpointed to exact pixel regions rather than accepted wholesale:
  - `app-header-linux.png` — all significant diff confined to a 32x32 box at
    (37,21), exactly the `BrandMark size={32}` slot. Baseline shows the retired
    "navy gradient square with a serif E" placeholder that `styles/shell/BrandMark.tsx`
    replaced (ADR-0027/0028). Last blessed 2026-04-23, before the unification.
    **Verdict: stale baseline, app correct.**
  - `empty-state-mobile-linux.png`, `error-state-mobile-linux.png`,
    `workspace-mobile-linux.png` — all significant diff confined to a 34x16 box
    at (49,236) resp. (49,270): the filter-count badge. Baseline renders "2";
    the app renders no badge. That "2" *is* bug #674 ("counts the seeded CH/de
    defaults as user choices"), fixed in `80db9b92`. That commit was already an
    ancestor of `e768018d`, the commit that blessed these baselines five minutes
    later — so they were generated against a stale build.
    **Verdict: stale baseline, app correct.**
  - `admin-run-detail-v2-linux.png` — page subtitle changed from "Source

    **Verdict: stale baseline, app correct.**
  - `detail-sheet-mobile-linux.png` — 1 pixel over Playwright's per-pixel
